CLAUDE.md v2 (ADR-0005, D-192). Rules only; every rule is enforced by a hook, lint rule or CI gate named beside it. History: docs/GOVERNANCE-HISTORY.md · decisions: docs/DECISION_LOG.md · plan: docs/STREAMS.md.

ARCHITECTURE (non-negotiable — gate ①: eslint-plugin-boundaries, no-db-outside-with-context; gate ⑤: guards)
- Modular monolith, hexagonal per module (domain/ application/ infrastructure/ api/ tests/ per use case). Cross-module imports fail lint; modules talk through packages/events (catalog) and packages/contracts.
- NestJS (Fastify) · Drizzle · Zod→OpenAPI · XState v5 · pg-boss · React/TanStack/shadcn · Expo · PWA (PDA) · Docker Compose Tier 0 · Terraform-ready Tier 2.
- Domain events are written to platform.outbox IN THE SAME TRANSACTION as the state change (writeOutboxEvent(tx, …)). platform.domain_events is retired — never write to it.
- Every write endpoint requires an Idempotency-Key (packages/api-kit requireIdempotencyKey; registry invariant). Every mutable aggregate has a version column.
- All DB access goes through withContext(ctx, fn) (sets the RLS GUCs; refuses to run unless PG_APP_USER names a non-superuser role). RLS is enabled on every operational table (G7). Every column is classified in identity.column_classification (G6).
- No table, column or business rule outside docs 01 / 13 / 13B / 019 / 40. Missing → STOP and file a schema-change request (docs/notes/SCR-*.md); never invent.

BUILD METHOD (doc 36 §5 — every slice, in order, never skipping; pre-commit ①② and CI ①–⑥ enforce)
  brief → pre-build review (pg-reviewer) → Gherkin scenario + Zod contract → SQL migration with RLS (pre-migration review) → tests RED → domain until unit green → application until integration green → UI until acceptance green → close review → one commit.
- Unit of planning is a doc 40 Part E scenario (S1–S20). A doc-38 row is DONE only when its scenario is green in Playwright (docs/STREAMS.md).
- GOLDEN SLICE = WBS 2.9 "Receive inbound order". scripts/new-slice.sh <module> <use-case> replicates it; every slice starts from it. A hand-made tree is a review FAIL.
- ADRs live in docs/adr/ (template in docs/adr/README.md), only for a decision that changes the architecture or a rule here. Everything else → docs/CHANGELOG.md. Never create a new numbered package document.

AGENT CONSTRAINTS (copied verbatim into every agent file — gate ①)
- No `any`, `@ts-ignore`, `eslint-disable`. Never weaken a test to pass it. Never skip, disable or quarantine a test.
- No if/switch for state transitions — XState. No embedded UI strings — i18n (ar, en, hi, ur, bn, am). No magic numbers — constants or platform.thresholds. No console.log — pino (@pg-eos/logger).

AGENTS AND SESSIONS (routing pinned in .claude/agents/*.md — check-setup refuses `inherit`)
- pg-tester (sonnet) writes only tests/**, **/tests/**, *.test.*, *.spec.*, features/**, *.feature. pg-builder (sonnet; opus when the slice carries a migration, RLS, permissions or platform/identity/billing core — the brief's `builder:` line decides, scripts/brief-check.sh refuses a brief without it) writes only inside its lock, never a test. pg-reviewer (opus) writes nothing; reviews the brief + RED before build and the slice at close. scripts/scribe.mjs writes PROJECT_STATE, LANE_LOCKS and the CHANGELOG template.
- One Master session owns state, merges, migration numbers and each wave's contracts (commits them before the wave starts) and builds nothing (pg-reviewer checks the author of every slice). M-core (branch core/<wbs>, lane-M lock rows) builds the frozen-path and tooling tasks (ADR-0007). Two build lanes (one stream each) and one integration lane (Playwright, scenarios, greening); D-198 raises the cap for a third build lane, Stream C, once the Master claims a real `tasks/LANE_LOCKS.md` row for it and issues its brief — not started yet. A lane is one session, one slice, branch lane/<id>-<wbs> — in the cloud the branch names the lane (lane-guard.sh) —, its own database (bash scripts/lane-db.sh <id>; remote containers get Postgres from .claude/hooks/session-start.sh), one report to the Master, then it ends.
- Locks: tasks/LANE_LOCKS.md, one row per stream or module or module/use-case, validated by scripts/check-locks.sh (pre-commit ⓐ, CI ①). A lane writes only inside its lock plus tests/; a worker needing another file STOPS and reports. Frozen for every lane: packages/*, database/schema/*, packages/contracts/_shared/*, CLAUDE.md, .claude/* — built by M-core under its lane-M lock rows (`packages/<name>`, `tooling`; CLAUDE.md stays with the Master — lane-guard.sh), merged first; lanes rebase after each M-core merge.
- Migrations: numbers issued by the Master only, database/migrations/NNNN_<lane>_<slug>.sql (register in database/migrations/README.md), forward-only, RED tests named in tasks/backlog/MIGRATION-REQUEST-<lane>.md before the file exists (lane-guard.sh refuses it otherwise), pre-migration review mandatory.
- Merge queue (Master only, D-197/ADR-0007 Phase 2): a PR touching no migration, frozen path or lock file gets rebase auto-merge from the Master once CI ①–⑥ is green and `review` posts PASS (native merge queue unavailable — repo owner is a GitHub User account; a main ruleset instead requires ①–⑥ + up-to-date branches, linear history, no force push). Migration PRs (in number order, D-179), M-core PRs and lock PRs stay manual, one at a time: rebase on main → gates ①–③ → pnpm guards:run → rebase merge (linear history) → delete the branch in the same step. A behind-main PR is rebased before auto-merge is enabled on it. Gate ⑦ (arm64 image build + compose smoke) runs nightly (nightly.yml + workflow_dispatch), not per PR — per-PR CI is ①–⑥. Lanes never merge lanes; max six concurrent cloud sessions (Master, M-core, lanes 1–2, integration, and room for a third build lane once claimed — ADR-0007 D-198; one advisory GM session is not counted), rising to seven if the 2026-09-30 Phase-2 evaluation holds the merge SLA; a local host keeps max three concurrent sessions and the RUNBOOK §2 memory rule.
- Session limits and rotation (ADR-0007 Decision 5, the Master's hourly watchdog routine): each role has a context ceiling and a unit of work; at the ceiling the session hands over at the next clean point — pushed branch, handover packet, successor session, ACK, then the predecessor is archived. The watchdog also auto-archives, without a handover, any session whose handover was already ACKed, whose work already merged, or which has sat idle over 2 h with no open PR (D-198). One writer per role at any time; a successor reads CLAUDE.md, PROJECT_STATE, then its packet (docs/notes/handover-<role>.md, or the lane's slice brief) before any other action.

REVIEW (doc 36 §5-4 applied literally)
- Findings are `blocking` or `nit`; nits are fixed in the same fix round; there is no "polish" backlog row. REVIEW CAP: round 1 → one fix round → round 2. Round 2 FAIL → commit only the PASS subset; every open finding becomes a `<WBS> part n+1` row in tasks/MASTER_BACKLOG.md; no round 3. Opus escalation only for a finding that cannot be split (security, audit chain, RLS) and it is the last round.
- Budget in every brief: ≤ 8 files / 1,000 lines read (brief-check.sh), ≤ 150k tokens per slice; more than 2× splits the slice before the next review. A slice that ends without its feat(<WBS>) commit has failed unless it stopped on a REAL BLOCKER.

TESTING (doc 36 §5-5 — gates ②③④⑤, nightly)
- domain/ unit coverage ≥ 90% · property tests on every invariant (fast-check) · contract tests from the OpenAPI registry · S1–S20 green in Playwright (20/20 governs) · mutation score ≥ 75% on domain/ (Stryker, nightly) · guards G1–G18 (doc 40 Part F): G1–G17 zero rows or the stated pass condition (G13 100 unique · G15 all scenarios pass · G16 ≥ 75% · G17 ≤ 2 s); G18 report-only. A single G1–G17 failure blocks merge and deploy. Run the module's test project and the guards, never a full pnpm test locally; CI runs the suite.

GIT (.githooks/commit-msg + pre-commit, activated by scripts/install-hooks.mjs on every pnpm install)
- Conventional commits; first line exactly `type(WBS): description` with a WBS ID from docs/package/38-WBS.md or `X`; types feat fix docs chore test refactor perf build ci style revert wip. Body trailers: `Model:` · `Delegated:` · `Review: PASS(<n> findings, <r> rounds)` (feat/fix). A docs(X) needs `GM-Directive: "<verbatim>"` or `Decision: D-NNN`; a second chore(X)/docs(X) on one day needs `Override: GM` + the directive.
- ONE commit per completed task: code + tests + state + backlog + CHANGELOG. The previous task's hash is recorded in PROJECT_STATE inside the next task's commit. Migrations are forward-only. Never commit secrets, .env, keys, dumps, backups. Push per docs/RUNBOOK.md; the working tree is clean at session end.

DOCUMENTS (the package is the documentation)
- Sessions read CLAUDE.md, docs/PROJECT_STATE.md (generated, ≤ 40 lines), the module brief (.claude/briefs/<module>.brief.md, ≤ 120 lines) and the slice brief — nothing else; a successor session also reads its handover packet (ADR-0007 Decision 5). Package documents are opened only at the section the brief cites.
- CHANGELOG entry ≤ 12 lines (what · why · files · review · tokens). docs/notes/ holds only SCR-* with an open item, GM-named files, briefs of active slices and the live handover packets (ADR-0007); a slice deletes its brief and the SCRs it applies in its own commit. At most one chore(X)/docs(X) commit per day; weekly target ≥ 75% feat/fix (scripts/gov-ratio.sh).
- A decision is one CHANGELOG line; a D-id only for a verbatim GM directive or an ADR. Closing report to the GM in Arabic, ≤ 15 lines: commit · gates · findings · defaults · questions · next. Code, commits, tests and docs stay in English.
