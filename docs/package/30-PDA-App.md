**وثيقة 30 · PG-EOS · الإصدار 4.0 · 21/09/2026**

> **v4 — حالة الوثيقة:** مرجعية · **الحاكم عند التعارض:** 40 §B1/§C3/§D · EXECUTION-MASTER-v4 §1.2 (G-07) · 19 §2 (صيغة الكود) · **التصحيحات المطبّقة في v4:** OPS-43, OPS-44, OPS-45, OPS-47, OPS-48 · **القرارات المفتوحة سابقاً:** مُغلقة في EXECUTION-MASTER-v4 §1.

# 1. الفرق عن تطبيق السائق

| | **PDA** | تطبيق السائق |
|---|---|---|
| المستخدم | عامل مستودع | سائق |
| المكان | داخل المخزن | الطريق |
| الجهاز | **PDA صناعي بماسح ليزري** | جوال |
| المدخل الأساسي | **المسح — الكتابة استثناء** | مسح + لمس |
| الشبكة | ضعيفة أو منقطعة داخل الرفوف | متقطّعة |
| الجلسة | وردية كاملة · مئات العمليات | مهام اليوم |
| اللمس | **بقفاز** | بيد حرة |
| الخطأ | يُكشف **لحظته** لا بعد ساعات | عند الإقفال |

**النتيجة التصميمية:** PDA ليس نسخة مصغّرة من الواجهة الإدارية. **هو أداة مسح بشاشة تأكيد** — لا أكثر.

# 2. المبادئ التسعة

| # | المبدأ | التطبيق |
|---|---|---|
| **W1** | **المسح هو المدخل** | كل خطوة تبدأ بمسح · الكتابة عند الاستحالة فقط |
| **W2** | **خطوة واحدة في الشاشة** | لا نموذج متعدد الحقول — سؤال واحد وجواب واحد |
| **W3** | **الخطأ يُمنع لا يُصحَّح** | مسح خاطئ يُرفض فوراً بصوت واهتزاز — لا يُحفظ ثم يُراجَع |
| **W4** | **يعمل دون اتصال بالكامل** | كل العمليات محلياً · مزامنة عند العودة |

# 3. الشاشات التسع

## 3-0 الرئيسية

```
┌────────────────────────────┐
│ ناريش · وردية صباحية       │
│ 🟢 متصل        ⏱ 06:42     │
├────────────────────────────┤
│                            │
│   ┌──────────┐ ┌─────────┐ │
│   │ 📥 استلام │ │📦 تخزين │ │
│   └──────────┘ └─────────┘ │
│   ┌──────────┐ ┌─────────┐ │
│   │ 🔍 التقاط │ │✅ تدقيق │ │
│   └──────────┘ └─────────┘ │
│   ┌──────────┐ ┌─────────┐ │
│   │ 🚚 تحميل  │ │📊 جرد   │ │
│   └──────────┘ └─────────┘ │
│   ┌──────────┐ ┌─────────┐ │
│   │ ↔️ تحويل  │ │↩️ مرتجع │ │
│   └──────────┘ └─────────┘ │
│                            │
│   [ 🔎 استعلام موقع/صنف ]  │
├────────────────────────────┤
│ مهامي اليوم: 3 مفتوحة      │
│ غير مزامَن: 0              │
└────────────────────────────┘
```

**ثماني مهام + استعلام.** الأيقونة والنص معاً — الأيقونة للأمّي، النص للقارئ.

## 3-1 الاستلام

```
مسح رقم أمر الاستلام
   ▼ الأمر معتمد؟ → لا: ⛔ «الأمر غير معتمد — راجع المشرف»
مسح باركود الصنف
   ▼ الصنف يخص هذا العميل؟ → لا: ⛔ «الصنف لعميل آخر»
   ▼ صنف غير مسجّل؟ → 🟡 «إلى الحجر — بلّغ المشرف»
الكمية ─ لوحة أرقام كبيرة
الدفعة ─ مسح أو كتابة
الصلاحية ─ مسح أو تقويم
   ▼ الصلاحية المتبقية < الحد؟ → 🟡 «حجر — قرار العميل خلال 48 س» (المالك: WH_MGR — EXEC §1.2)
📷 صورة ─ إلزامية عند الفرق أو التلف
   ▼
✅ «تم — 12 من 48 منصة»
```

**الشاشة تعرض دائماً:** العميل · الصنف · **العداد الحي (المُستلم/المتوقَّع)**.

## 3-2 التخزين

```
مسح المنصة أو الصنف
   ▼
┌──────────────────────────┐
│  ضع في                   │
│                          │
│     G3-14-2              │  ← 48 بكسل
│                          │
│  🟢 ميزانين أرضي · ممر 3 │
│  ⚖ الحد 750 كجم          │
└──────────────────────────┘
   ▼
مسح كود الموقع للتأكيد
   ▼ غير مطابق؟ → 🟡 «موقع مختلف — السبب؟» (قائمة مغلقة)
✅ تم
```

> **صيغة الكود سبع خانات `[P|G|M|T]a-pp-l`** (19 §2 — الحاكم). حرف القسم **أربعة فقط: `P` · `G` · `M` · `T`**؛ و`B` نوع رفّ إنشائي **لا قسم**. صُحِّحت في v4 أمثلة `B3-…` إلى `G3-…` (ميزانين أرضي = `G`) في §3-2 و§2 W8 و§4 (OPS-45).

**اقتراح الموقع آلي (A2):** شروط الصنف · تصنيف ABC · قرب موقع الصرف · السعة المتبقية · تخصيص العميل.

## 3-3 الالتقاط

```
┌──────────────────────────┐
│  أمر OUT-00317   3 / 9   │
│  ▓▓▓▓▓▓░░░░               │
├──────────────────────────┤
│  اذهب إلى                │
│     G2-08-1              │
│  الصنف: CL-00042-0137    │
│  الكمية:  12             │
│  الدفعة:  B2409-7 (FEFO) │
└──────────────────────────┘
   ▼ مسح الموقع → مسح الصنف → تأكيد الكمية
   ▼ نقص؟ → سبب من قائمة → 🔔 المشرف فوراً
▶ التالي
```

**التسلسل بالمسار الأقصر (A3)** — لا بترتيب سطور الأمر. الشاشة تقول **أين تذهب**، لا ما يوجد في السطر.

## 3-4 التدقيق

```
مسح رقم الأمر
   ▼ مسح كل بند
   ▼ مطابقة آلية
✅ 9/9 مطابق          أو    ⛔ بند 4: العدد 10 والمطلوب 12
[ تأكيد المدقّق ]                [ إعادة عدّ ] [ تبليغ ]
```
**المدقّق ≠ الملتقط — مفروض دائماً** (INV-C3-6 · EXEC §1.2 **FIXED**). النظام يرفض أن يدقّق الشخصُ التقاطَه هو. **التجاوز بيد `WH_SUP` فقط، بسبب مسجَّل، ويظهر في تقرير شهري** (v4 — OPS-44).

## 3-5 التحميل

```
مسح الشحنة → مسح المركبة → تأكيد
   ▼ العداد الحي: 18 من 24
   ▼ ⛔ شحنة لعميل آخر → رفض فوري
[ إقفال التحميل ]  ← يُرفض إن نقص شيء
```

## 3-6 الجرد

```
مسح الموقع
   ▼ ⚠️ العدّ الأعمى — الرصيد النظامي لا يظهر
عدّ ← أدخل الكمية
   ▼ فرق؟ → 🟡 «أعد العدّ» (إلزامي)
   ▼ الفرق باقٍ → سبب من قائمة → المشرف
▶ الموقع التالي
```

**العدّ الأعمى إلزامي** — إظهار الرصيد النظامي يُفسد الجرد.

## 3-7 التحويل والمرتجع

| التحويل | المرتجع |
|---|---|
| مسح من موقع → الصنف → الكمية → إلى موقع | مسح الشحنة → سبب الإرجاع (قائمة) |
| تأكيد السعة آلياً | الحالة: صالح / تالف → 📷 |
| | الوجهة: مخزون / تالف / فحص |

## 3-8 الاستعلام

```
مسح أي باركود — موقع أو صنف أو شحنة
   ▼
موقع  → ما فيه · العميل · المساحة المتبقية
صنف   → أين يوجد · الكمية · الدفعات · الصلاحيات
شحنة  → حالتها · أين · مع من
```

**شاشة قراءة فقط.** يستخدمها العامل والمشرف عشرات المرات يومياً — وهي أكثر شاشة تُفتح.

# 4. لغة الخطأ

| الحالة | ❌ لا يُقال | ✅ يُقال | التنبيه |
|---|---|---|---|
| صنف لعميل آخر | «غير مسموح» | «هذا الصنف لعميل آخر — أعده للمشرف» | صوت + اهتزاز مزدوج |
| موقع ممتلئ | «خطأ السعة» | «ممتلئ — ضع في G3-15-1» | صوت |
| وزن زائد | «تجاوز الحد» | «الموقع يتحمل 750 كجم — هذه 900» | صوت + اهتزاز |
| صلاحية قصيرة | «مرفوض» | «الصلاحية 45 يوماً — إلى الحجر» | صوت |
| باركود مكرر | «مكرر» | «مُسح قبل دقيقتين — تخطَّه» | نغمة قصيرة |
| موقع محجوب | «محجوب» | «هذا الموقع درج — لا تخزين فيه» | صوت + شاشة سوداء |
| بلا شبكة | ❌ لا رسالة | 🟡 مؤشر صامت + «غير مزامَن: 7» | لا شيء |

**القاعدة:** الرسالة تقول **ما يفعله الآن** — لا ما حدث. عامل لا يقرأ العربية يفهم الأيقونة واللون والصوت.

# 5. العمل دون اتصال

```
بدء الوردية → تحميل محلي:
   مهام اليوم · أصناف عملاء اليوم · المواقع · الحدود · القوائم
      ▼
كل عملية → طابور محلي بمعرّف فريد (UUID)
      ▼
شبكة متاحة → دفع بالترتيب
      ▼
الخادم يرفض المكرر بالمعرّف
      ▼
تعارض → الخادم هو المرجع · يُبلَّغ العامل
```

| البند | القاعدة |
|---|---|
| السعة | **٧٢ ساعة** عمل محلياً (G-07 — الحاكم) |
| الصور | تُضغط ≤ ٢٠٠ ك.ب · تُرفع عند الشبكة |
| **الوقت** | الجهاز يسجّل · **الخادم يختم** · الفارق الكبير يُعلَّم |
| الطابور | يبقى حتى التأكيد — لا يُفقد بإغلاق التطبيق |
| مؤشر «غير مزامَن» | ظاهر دائماً — **أخضر ٠ · أصفر ١–٢٠ · أحمر > ٢٠** |
| قفل الوردية | **لا تُقفل وردية بطابور > ٠** |

# 6. الجهاز والمصادقة

## 6-1 المصادقة — **G-07 · نموذج الجهاز المشترك** (v4 — قرار حاكم · EXEC §1.2)

| البند | **القيمة المعتمدة** |
|---|---|
| **نموذج الجهاز** | **مشترك** — الجهاز أصل مسجَّل في سجل الأصول (`device → registry`)، لا يخص عاملاً بعينه |
| **من يدخل** | **أي عامل مصرَّح له** — التبديل بين العمال **لا يحتاج موافقة** |
| **الجلسة** | **جلسة نشطة واحدة لكل جهاز** |
| **الدخول** | **رمز الموظف + PIN من ٦ أرقام** |
| **تخزين الرمز** | **تجزئة PIN تُخزَّن محلياً على الجهاز بعد أول دخول متصل** — ولا كلمات مرور مخزَّنة على الخادم |
| **إعادة التحقق** | **OTP أسبوعياً وهو متصل** |
| **نافذة العمل دون اتصال** | **٧٢ ساعة** |
| **مفتاح توقيع الجهاز** | لكل جهاز مفتاح توقيع؛ **كل عملية في الطابور تُختم بـ`user_id` المنفِّذ + توقيع الجهاز + توقيت العملية** |
| **قبول العملية** | تُقبل إذا كان الرمز صالحاً **وقت تنفيذ العملية** لا وقت المزامنة |
| **جهاز ملغى** | **طابوره يُحجر لمراجعة المشرف** — لا يُقبل ولا يُحذف |
| **بدء الوردية** | متصل (بصمة وجه)؛ وعند التعذّر عَلَم `offline_start` |
| **إقفال الوردية** | إنهاء الجلسة بطابور معلّق **مسموح (تسليم وردية)**؛ الإقفال يتم تلقائياً عند مزامنة آخر عملية — **ولا تُعلَّم وردية مقفلة وطابورها > ٠** |

> كانت الوثيقة تكتفي بصف واحد «دخول برقم الموظف + رمز» بلا تحديد **٦ أرقام** ولا **OTP الأسبوعي** ولا الجلسة الواحدة ولا مفتاح التوقيع ولا حجر الطابور — وهو نموذج مصادقة ناقص لا يُبنى عليه (OPS-43). نافذة الـ٧٢ ساعة وحدها كانت مطابقة.

**الفرق عن تطبيق السائق (للمقارنة — التفصيل في 35 §13):** السائق **جهاز شخصي** · جهاز واحد لكل سائق · تسجيل بـ**OTP مرة واحدة ثم تحديث 30 يوماً** · **جهاز جديد = موافقة مشرف** · **offline 7 أيام**.

## 6-2 مواصفة الجهاز

| البند | المواصفة |
|---|---|
| النوع | PDA صناعي أندرويد (فئة Honeywell CT · Zebra TC) |
| الماسح | ليزري 1D/2D — **لا كاميرا** |
| الوضع | **Keyboard Wedge** — المسح يدخل كنص مباشرة |
| الشاشة | ≥ ٤ بوصات · تعمل بالقفاز |
| البطارية | وردية كاملة + احتياطي |
| المتانة | IP65 · سقوط ١.٥ م |
| القفل | **وضع الكشك** — لا يُفتح إلا التطبيق |
| التوزيع | **الموجود + ٢٠٪ احتياطي** (قرار مُغلق — EXEC §1.2) |

**التطبيق:** PWA يُخدَّم من النظام · يعمل دون اتصال · يُثبَّت على الشاشة الرئيسية. **لا متجر تطبيقات.**

# 7. مكافحة التلاعب

| الخطر | المعالجة |
|---|---|
| مسح بلا مناولة فعلية | تسلسل إلزامي: موقع ← صنف ← كمية · تخطّي خطوة يُرفض |
| نسخ باركود على ورقة | صورة إلزامية عند الفرق والتلف |
| جرد بإدخال الرصيد النظامي | **العدّ الأعمى** |
| تدقيق ذاتي | **المدقّق ≠ الملتقط** — مفروض دائماً؛ **التجاوز بيد `WH_SUP` بسبب مسجَّل يظهر في تقرير شهري** (v4) |
| مشاركة الجهاز | **رمز الموظف + PIN ٦ أرقام** (تجزئة محلية بعد أول دخول متصل) · **جلسة نشطة واحدة لكل جهاز** · **OTP أسبوعي** · كل عملية مختومة بـ`user_id` + توقيع الجهاز (§6-1) |
| **جهاز ملغى أو مفقود** | **إبطال فوري + حجر طابوره** لمراجعة المشرف (v4) |
| تغيير ساعة الجهاز | **الختم من الخادم** · والعملية تُقبل بصلاحية الرمز **وقت تنفيذها** |

**ما يمكن استنتاجه من الوصف وحده:** تطبيق **تنفيذ توصيل** لا تطبيق دورة حياة سائق — وهو ما بُنيت عليه **وثيقة 35** (التي حلّت محل وثيقة 16 المتقاعدة).

**ما لا يمكن استنتاجه — وأحتاجه منك:**

| # | ما أحتاج رؤيته | ما سأستخرجه منه |
|---|---|---|
| 1 | شاشة قائمة المهام | الترتيب · ما يظهر لكل شحنة · كثافة المعلومة |
| 2 | مسار التسليم الناجح كاملاً | **عدد النقرات من فتح المهمة إلى الإقفال** |
| 3 | شاشة أسباب الفشل | هل القائمة مغلقة؟ كم سبباً؟ |
| 4 | شاشة COD | كيف يُؤكَّد المبلغ · ماذا عند النقص |
| 5 | رسالة خطأ واحدة | لغة الخطأ — أهم ما يُقارَن |
| 6 | شاشة بلا شبكة | هل يعمل دون اتصال فعلاً |
| 7 | أي شاشة أرباح أو حضور | **أتوقع: لا توجد — وهي ميزتنا التنافسية** |

**سبع لقطات شاشة تكفي.** أقارنها بنداً ببند وأحدّث **وثيقة 35** بما يستحق الأخذ وما يستحق التجاوز.
