# القسم الأول: الأسطول (M09)

## 1. ما كان ناقصاً

وثيقة 03 §8 غطّت آلة الحالات فقط. الناقص: **جدولة الصيانة · دورة الحادث والتأمين · ربط الوقود بالتكلفة · تكلفة المركبة الحقيقية**.

## 2. المخطط الإضافي

> **التعريف الحاكم في `database/13B`.** ما يلي مقتطف الأعمدة والقيود التي يتوقف عليها نصّ هذه الوثيقة.

### 2-1 فترات الصيانة الوقائية — البذرة الحاكمة

**القيم محسومة في EXEC §1.3** (افتراضات لكل نوع مركبة، قابلة للتعديل لنوع بعينه):

| المهمة | `interval_km` | `interval_days` | القاعدة |
|---|---|---|---|
| **زيت وفلاتر** | **5,000 كم** | **90 يوماً** | **أيهما أسبق** |
| **فرامل** | **20,000 كم** | — | بالكيلومترات |
| **إطارات** | **40,000 كم** | — | بالكيلومترات |
| الفحص الدوري القانوني | — | **حسب القانون** | بتاريخ انتهاء الفحص |

```sql
-- مقتطف: العمودان معاً، و«أيهما أسبق» لا «الكيلومترات فقط»
  interval_km   int,          -- 5000 زيت وفلاتر · 20000 فرامل · 40000 إطارات
  interval_days int,          -- 90 لزيت والفلاتر — أيهما أسبق يُطلق الاستحقاق
  alert_before_km   int default 500,
  alert_before_days int default 14,
```

> **تصحيح مطبَّق (ADM-32 المرافق):** كان §3 يقول «الصيانة الوقائية **بالكيلومترات لا بالتاريخ**» بينما العمودان `interval_km` و`interval_days` موجودان وEXEC يحسمها «**5,000 كم أو 90 يوماً**». المعتمد: **أيهما أسبق**. مركبة قليلة الاستخدام لا يعني زيتها أنه لم يتقادم.

## 3. الضوابط

| الضابط | السلوك |
|---|---|
| **وثيقة منتهية** | **حاجز صلب** — المركبة لا تُسند لمهمة |
| قراءة العداد | **إلزامية** مع كل تعبئة — بدونها لا يُسجَّل الصرف |
| استهلاك شاذ | انحراف > ٢٠٪ عن معدل المركبة (٩٠ يوماً) → `is_anomaly` + تنبيه |
| الصيانة الوقائية | **بالكيلومترات أو بالزمن — أيهما أسبق** (زيت وفلاتر 5,000 كم / 90 يوماً · فرامل 20,000 كم · إطارات 40,000 كم) · تنبيه قبل ٥٠٠ كم أو ١٤ يوماً |
| صيانة مستحقة متأخرة > ١,٠٠٠ كم | المركبة تُعلَّم «تحتاج صيانة» — تسنيدها يتطلب تجاوزاً من مدير الأسطول (`FLEET_MGR`) بسبب مسجَّل |
| الحادث | تقرير خلال ٢٤ ساعة · صور إلزامية · **عدم الإبلاغ الفوري بند جزائي VEH-06** |
| **التحميل على السائق** | **بقرار بعد تحقيق — لا خصم تلقائي — وبحدٍّ أقصى قيمة تحمّل التأمين (`deductible`)** · مفروض بقيد لا بسياسة مكتوبة |
| بطاقة وقود لموظف غادر | تُلغى آلياً عند إخلاء الطرف |

### 3-1 تحميل الحادث على السائق — القاعدة والقيد

**القاعدة المحسومة (EXEC §1.3):** «**Only after investigation; capped at insurance deductible**» — شرطان لا شرط واحد.

| الشرط | التطبيق |
|---|---|
| **بعد تحقيق** | `driver_at_fault` لا يُحدَّد إلا بإغلاق التحقيق · و`disciplinary_case_id` يربط الواقعة بملف انضباطي وفق 15 (`VEH-04`) بإجراءات م.37 كاملةً |
| **بسقف التحمّل** | `charged_to_driver ≤ deductible` — **مفروض بقيد في القاعدة** |
| ما فوق السقف | على التأمين أو على الشركة — **لا على السائق** |
| الخصم | يمرّ بسقف المادة 38 (5 أيام شهرياً) كأي خصم جزائي، ولا يُرحَّل قبل مهلة التظلّم |

```sql
-- مقتطف: السقف مفروض لا موصوف (التعريف الحاكم في 13B)
alter table tms.accidents
  add constraint charge_within_deductible
  check (charged_to_driver <= coalesce(deductible, 0));
```

> **التصحيح المطبَّق (ADM-32):** كان النصّ يذكر التحقيق **ويُسقط سقف مبلغ التحمّل**، ويحمل المخطط العمودين `deductible` و`charged_to_driver` **بلا قيد يربطهما** — أي إمكان تحميل السائق مبلغاً يفوق تحمّل التأمين كله.

## 4. تكلفة المركبة الحقيقية

```
تكلفة المركبة الشهرية = إهلاك + تأمين + صيانة + وقود + رخص
                       ÷ عدد الشحنات أو الرحلات
                       = تكلفة الرحلة الحقيقية
                              ▼
                  تُخصَّص لعميلها (assigned_client_id)
                              ▼
                     تدخل لوحة الربحية
```

| مؤشر | ما يكشفه |
|---|---|
| تكلفة الكيلومتر لكل مركبة | المركبات المكلفة تشغيلياً |
| زمن التعطّل (downtime) | أثر الصيانة على الطاقة |
| كم/لتر لكل مركبة وسائق | هدر الوقود وسوء الاستخدام |
| تكلفة الحوادث لكل سائق | مؤشر سلوك — لا مالي فقط |
| عمر الأسطول وتكلفته | **قرار الاستبدال** |

## 9. تهيئة عميل جديد

```
① عقد ساري + أسعار معتمدة
② إنشاء CLIENT_ADMIN → دعوة بالبريد
③ الأدمن ينشئ مستخدميه ويحدد أدوارهم
④ جلسة تعريفية ٣٠ دقيقة + دليل مصوّر
```

### 12-1 إثبات التسليم (POD) — فصل السجل عن الصورة

**التصحيح المطبَّق (ADM-33):** كان الصفّ الواحد يصنّف POD «تشغيلية — ٥ سنوات»، بينما EXEC §1.4 و40 Part G يحسمان «**photos 60 days with automatic `legal_hold`**». والصفّان ليسا متعارضين متى فُصل **السجل** عن **الملف**:

| المكوّن | المدة | لماذا |
|---|---|---|
| **سجل POD** — من استلم · متى · الإحداثيات · التوقيع · `sha256` للصورة | **٥ سنوات** | هو الدليل الأساسي في نزاع التسليم، وحجمه لا يُذكر |
| **ملف الصورة** | **٦٠ يوماً** | كلفة تخزين حقيقية، ونادراً ما تُطلب بعد شهرين |
| **الاستثناء** | **`legal_hold = true` تلقائياً** على أي صورة مرتبطة بنزاع أو شكوى أو جزاء أو مطالبة تأمين | بلا هذا الاستثناء يهدم الحذف ما تبنيه 09 §9 («لا تنازل عن معيار إثبات التسليم») |

```sql
-- مقتطف: أعمدة الحفظ على tms.proof_of_delivery (التعريف الحاكم في 13B)
  sha256       text,          -- بصمة الصورة — تبقى بعد حذف الملف وتثبت عدم التبديل
  legal_hold   boolean not null default false,
  retain_until date,
```

| الضابط | القاعدة |
|---|---|
| وضع الحجز | آلي عند فتح نزاع أو شكوى أو ملف جزائي أو مطالبة تأمين مرتبطة بالشحنة |
| رفع الحجز | بإغلاق السبب فقط — وبسبب مسجَّل في التدقيق |
| **تفعيل الحذف** | **لا يُفعَّل قبل المرحلة 6** من 38 — إلى حينها لا يُحذف شيء |
| البصمة | `sha256` يبقى في السجل بعد حذف الملف، فيثبت أن الصورة التي كانت هي ما كانت |

## 13. الإصدارات والتجميد

> **التعريف الحاكم لـ`platform.documents` في `database/13B`** (و40 §B4). المقتطف التالي هو الأعمدة التي تفرضها قواعد هذا القسم:

```sql
-- مقتطف من platform.documents — لا يُنفَّذ من هنا
  status        text not null default 'issued',  -- issued · superseded · void
  superseded_by uuid,                            -- الإصدار الجديد لا يحذف السابق
  frozen        boolean not null default false,  -- المستند المالي المعتمد مجمّد
  legal_hold    boolean not null default false,  -- يمنع الحذف حتى بانتهاء المدة
  retain_until  date,
  signed_at     timestamptz,
  signed_by     text,
  signature_url text,
  checksum      text                             -- SHA-256 للنسخة
```

| القاعدة | التطبيق |
|---|---|
| **مستند مالي معتمد = مجمّد** | لا يُعدَّل · التصحيح بمستند جديد يشير إليه |
| الإصدار الجديد | لا يحذف السابق — يُعلَّم `superseded_by` |
| **بصمة التحقق (checksum)** | لكل ملف — تكشف أي تعديل لاحق |
| **الحجز القانوني** | `legal_hold` يمنع الحذف حتى بانتهاء المدة — عند نزاع قائم |
| الإتلاف | بعد المدة + بلا حجز · **بمحضر إتلاف مُوقَّع** · **ولا يُفعَّل قبل المرحلة 6** |
| البحث | بالرقم · التاريخ · الكيان · العميل · الموظف · النوع |
