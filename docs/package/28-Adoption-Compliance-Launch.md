# القسم الأول: التبنّي والتدريب

## 1. المبدأ

**النظام الممتاز الذي لا يُستخدم قيمته صفر.** وتاريخك يثبت ذلك: تطبيق حي بـ٢٩١ شاشة **يفتحه حسابان من اثني عشر**.

## 2. لماذا لم يُستخدم النظام السابق — ولا يُكرَّر

| السبب | العلاج في PG-EOS |
|---|---|
| لم يُشارَك مع أحد | **المشاركة قبل البناء لا بعده** — كل موديول يُسلَّم لمستخدميه فور فتح بوابته |
| الشاشات تعرض صفراً | **مكوّن الحالة الفارغة** يقول ما ينقص ومن يملكه — **إلزامي بنصّ 40 §D1**، ويُبنى في المهمة **0.19** من 38 |
| لا تدريب | برنامج مُلزم لكل دور قبل الوصول |
| لا فائدة للمستخدم نفسه | **شاشة أرباح السائق · شاشة نواقص المشرف** — منفعة شخصية مباشرة |
| لا أحد مسؤول عن الاستخدام | **مالك موديول بالاسم** + مؤشر تبنّي شهري |

## 3. المستخدمون الخارقون (Super Users)

**شخص واحد لكل موديول — من الميدان لا من الإدارة.**

| الموديول | الملف المطلوب |
|---|---|
| المستودع | مشرف مستودع يعمل يومياً |
| التوصيل و iMile | مشرف محطة |
| الكول سنتر | وكيل أقدم |
| المالية | محاسب |
| الموارد البشرية | مسؤول شؤون موظفين |
| الأسطول | فني أو مشرف أسطول |

| دوره | التفصيل |
|---|---|
| يختبر قبل الإطلاق | يجد ما لا يجده المبرمج |
| يدرّب زملاءه | الميداني يقنع الميداني |
| **خط الدعم الأول** | قبل مالك النظام |
| يجمع الملاحظات | ويرفعها أسبوعياً |
| يقرّ الجاهزية | **لا يُطلق موديول بلا إقراره** |

## 4. برنامج التدريب

| الدور | المدة | الصيغة | القبول |
|---|---|---|---|
| عامل مستودع / PDA | ٩٠ دقيقة | عملي على أجهزة حقيقية | ينفّذ استلاماً وصرفاً وجرداً بلا مساعدة |
| سائق | ٦٠ دقيقة | عملي على التطبيق | يكمل تسليماً كاملاً مع POD و COD |
| وكيل كول سنتر | ٩٠ دقيقة | محاكاة | يفتح تذكرة ويربطها بشحنة ويقفلها |
| مشرف | ٣ ساعات | عملي + حالات | يعتمد · يعالج استثناءً · يقرأ لوحته |
| مالية | ٤ ساعات | دورة شهر كاملة | يجري دورة فوترة تجريبية من طرف لطرف |
| مدير | ساعتان | لوحته + تقاريره | يفسّر مؤشراته ويتخذ قراراً منها |
| **المدير العام** | ساعتان | اللوحة والقرارات | — |

**مواد إلزامية:** دليل مصوّر لكل دور · مقاطع ٩٠ ثانية لكل عملية · **بطاقة جيب** لكل عامل · قناة أسئلة.

**اللغات الست: عربي · إنجليزي · هندي · أردو · بنغالي · أمهري** (`ar, en, hi, ur, bn, am` — 40 الخاتمة و38 / 3.22؛ v4: كانت أربعاً هنا). التدريب بلغة لا يفهمها المتدرّب تدريب لم يحدث.

## 5. الدعم

| المستوى | من | النطاق | الاستجابة |
|---|---|---|---|
| L1 | المستخدم الخارق | كيف أفعل · خطأ إدخال | فوري |
| L2 | مالك النظام | خلل وظيفي · صلاحيات · بيانات | ≤ ٤ ساعات عمل |
| L3 | مطوّر النظام | عيب برمجي · أداء | ≤ يوم عمل |
| التصعيد | المدير العام | قرار أو موارد | — |

**فترة الرعاية المكثّفة:** أسبوعان بعد كل موديول — المستخدم الخارق في الموقع، ومالك النظام متاح، ومراجعة يومية ١٥ دقيقة.

## 6. مؤشرات التبنّي — شهرية

| المؤشر | الهدف | لماذا |
|---|---|---|
| مستخدمون فتحوا النظام هذا الأسبوع | **١٠٠٪** | هذا بالضبط ما فشل سابقاً (٢ من ١٢) |
| عمليات تُنفَّذ في النظام لا ورقياً | ≥ ٩٥٪ | |
| بلاغات دعم لكل مستخدم | متناقص شهرياً | |
| شاشات لم تُفتح ٣٠ يوماً | **تُراجع — وتُحذف إن بقيت** | |
| عمليات تُنجز من أول محاولة | ≥ ٩٠٪ | مؤشر جودة الواجهة |

> **شاشة لم تُفتح شهراً تُحذف.** هذه القاعدة وحدها تمنع تضخّم ٢٩١ شاشة مرة أخرى.

# 13. الكلمة الأخيرة

الحزمة مكتملة هندسياً. ثلاث طبقات — حاكمة ومرجعية وأدوات — تغطي البيانات والقواعد والعمليات والواجهة والتكاملات والنقل والاستمرارية والامتثال.

**وأكرّر ما قلته في سجل الفجوات، لأنه لم يتغيّر:**

نظامك الحالي فيه ١٥٢ اختباراً ناجحاً · ٩ موديولات · ٥١ جدولاً — **وعميل واحد مسجّل · صفر بصمة · صفر ملصق موقع**.

**ولا وثيقة في الحزمة كلها تُصلح ذلك.**

ما يُصلحه شيء واحد: **القرار رقم ١ في الوثيقة ٢٢ — تعيين مالك بالاسم لكل مجال من الاثني عشر، بموعد، ومساءلة شهرية.**

الهندسة جاهزة. البقية إدارة.
