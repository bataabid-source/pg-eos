# 3. دورة المشتريات

```
طلب شراء (أي قسم)
   ▼ فحص آلي: بند الميزانية · الرصيد المتاح
اعتماد حسب الصلاحية المالية (EXEC §1.1 — القيم في platform.thresholds):
   ≤ 100 د.ك          → اعتماد آلي              (purchase.auto_max)
   > 100 و ≤ 500      → مدير القسم الطالب        (purchase.manager_max)
   > 500 و ≤ 2,000    → المدير المالي            (purchase.cfo_max)
   > 2,000 د.ك        → المدير العام
   ▼
جمع عروض الأسعار — **3 عروض إلزامية فوق 500 د.ك**
   ▼
ترسية + تعليل الاختيار (ليس بالضرورة الأرخص — لكن السبب إلزامي)
   ▼
أمر شراء برقمه → إرسال للمورّد
   ▼
استلام + فحص → مطابقة ثلاثية: أمر الشراء ↔ الاستلام ↔ الفاتورة
   ▼
فرق → تجميد الدفع    |    مطابق → اعتماد الدفع
   ▼
قيد: مدين 5xxx أو 1500 أصول | دائن 2100 ذمم موردين
   ▼
الدفع → مدين 2100 | دائن 1100 بنك
```

## 3-0 مستويات الاعتماد — الجدول الحاكم

| الشريحة (د.ك) | المعتمِد | المنصب المسنَد اليوم | المفتاح |
|---|---|---|---|
| **≤ 100** | **لا معتمِد — اعتماد آلي** | — (النظام) | `purchase.auto_max = 100` |
| **> 100 · ≤ 500** | **مدير القسم الطالب** | `WH_MGR` · `DEL_MGR` · `SALES_MGR` · `FLEET_MGR` · `CC_MGR` بحسب مركز التكلفة | `purchase.manager_max = 500` |
| **> 500 · ≤ 2,000** | **المدير المالي** | `CFO` | `purchase.cfo_max = 2000` |
| **> 2,000** | **المدير العام** | `GM` | — |

**التصحيحان المطبَّقان في v4 (ADM-06):**

1. الشريحة **≤ 100 آلية** لا يدوية — الأتمتة موعودة في EXEC §1.1 وP11، وجعلها اعتماداً بشرياً يلغيها.
2. الشريحة **100–500** كانت مسندة إلى **«مدير العمليات» `OPS_DIR` — وهو منصب غير مشغول بنصّ 40 §B1**، أي سلسلة اعتماد ميتة على كل طلب شراء في هذه الشريحة. المعتمِد الآن **مدير القسم الطالب** (R-04).

> **قاعدة عامة (R-04):** `OPS_DIR` و`HR_MGR` **لا يظهران معتمِدَين في أي سلسلة** في هذه الوثيقة ولا في غيرها. البديل: مدير القسم الطالب ← `CFO` ← `GM`؛ واعتمادات الموارد البشرية (إعفاء السكن · جزاء D4 · الاستقدام) ← `GM`.
>
> **البذرة:** الحدود الأربعة تُبذر في `platform.approval_chains` و`platform.thresholds` (13B) — **لا تُكتب في الكود**.

## 3-1 الضوابط

| الضابط | لماذا |
|---|---|
| لا أمر شراء بلا بند ميزانية ورصيد كافٍ | يمنع الإنفاق خارج الخطة |

| **تخصيص التكلفة** | كل أمر شراء يحمل `cost_center` و `client_id` إن أمكن |

# 6. المعاملات الحكومية

```
طلب معاملة (استقدام · إقامة · رخصة · تجديد · ترخيص)
   ▼
تجميع المستندات (قائمة تحقق لكل نوع)
   ▼
تقديم للجهة → رقم مرجعي حكومي
   ▼
متابعة (حالة · ملاحظات · رسوم)
   ▼
إنجاز → استلام الوثيقة → رفعها للنظام → تحديث سجل الموظف/المركبة
```

| الحقل | الغرض |
|---|---|
| `transaction_type` · `authority` | نوع المعاملة والجهة |
| `related_table` · `related_id` | موظف · مركبة · كيان |
| `stage` · `stage_owner` · `sla_days` | **لا معاملة بلا مالك ومدة** |
| `government_ref` | المرجع الحكومي للمتابعة |
| `fees_paid` · `receipt_url` | التكلفة والإثبات |
| **`fee_voucher_no`** | **رقم سند الصرف من سلسلة `GOV` حصراً — لا من `RCT`** |
| **`due_at`** | **`timestamptz` يملؤه مُشغِّل** من `stage_started_at + sla_days`؛ والمتأخر شرط استعلام `due_at < now()` |

> **مُلغى في v4:** العمود `is_overdue` المولَّد — تعبيره يحوي `now()` وهو غير ثابت، فترفضه PostgreSQL 16 بخطأ `generation expression is not immutable`. البديل `due_at` بمُشغِّل (وهو ما فعله المخطط المطبَّق فعلاً).

## 6-1 سلسلة `GOV` — فصل عهدة الرسوم عن نقد العميل

**الضابط الحاكم (EXECUTION-MASTER-v4 §1.6 · 40 §C6):** المندوب (`PRO`) يمسك تيارَي نقد مختلفين تماماً، ولا يجوز خلطهما:

| التيار | السلسلة | المصدر | المآل |
|---|---|---|---|
| **مقبوضات العملاء** | **`RCT`** | العميل | تُخصَّص ضد فواتيره |
| **عهدة الرسوم الحكومية** | **`GOV`** | عهدة الشركة | تُصرف للجهات الحكومية بإيصال |
| **الفواتير الصادرة** | **`INV`** | — | — |

| القاعدة | التطبيق |
|---|---|
| كل صرف رسوم حكومية | سند من سلسلة **`GOV`** — `fee_voucher_no` إلزامي مع `receipt_url` |
| الخلط ممنوع | سند `RCT` لا يُستخدم لصرف رسوم، وسند `GOV` لا يُستخدم لقبض من عميل |
| **المطابقة** | **المدير المالي (`CFO`) يطابق السلسلتين منفصلتين شهرياً** — وهو الضابط التعويضي الوحيد لتجميع `PRO = ACCOUNTANT` |
| السلسلة `RCP` | **مُلغاة** — سلسلة يتيمة تُحذف من البذرة ومن `platform.counters` قبل إصدار أي سند |

**لوحة المندوب:** معاملاته مرتّبة بالاستعجال · المتأخرة بالأحمر (`due_at < now()`) · الرسوم المصروفة **بأرقام سندات `GOV`** · المعاملات المعلّقة لنقص مستند **مع اسم من يملك المستند الناقص**.

# 7. الاعتمادات الإدارية

محرّك اعتماد واحد يخدم كل الطلبات — لا مسار مستقل لكل نوع.

**كل معتمِد في الجدول التالي يشغل منصباً مشغولاً فعلاً** — لا `OPS_DIR` ولا `HR_MGR` في أي سلسلة (R-04).

| نوع الطلب | المسار | الدور المُسنَد |
|---|---|---|
| شراء | حسب الحد المالي (§3-0) | آلي / مدير القسم الطالب / `CFO` / `GM` |
| إجازة | المشرف المباشر → **المدير العام** | `<supervisor>` → `GM` (حتى يُشغل `HR_MGR`) |
| سلفة موظف | المشرف المباشر → **المدير المالي** | `<supervisor>` → `CFO` |
| استثناء سعري | مدير المبيعات → المدير المالي → **المدير العام** | `SALES_MGR` → `CFO` → `GM` |
| رفع حجز ائتماني | المدير المالي **أو** المدير العام — بسبب مسجَّل **ومدة محددة** | `CFO` \| `GM` |
| إشعار دائن | المدير المالي → **المدير العام** — **لا اعتماد آلي إطلاقاً** | `CFO` → `GM` |
| صرف عهدة | مدير القسم الطالب | `WH_MGR`/`DEL_MGR`/`SALES_MGR`/`FLEET_MGR`/`CC_MGR` |
| سفر ومهمة عمل | المدير المباشر → **المدير العام** | `<manager>` → `GM` |
| تعيين | مدير القسم الطالب → **المدير العام** | مدير القسم → `GM` |
| **إعفاء من خصم السكن** | **المدير العام حصراً — بسبب مسجَّل** | `GM` |
| **جزاء من الدرجة الرابعة / الفصل** | **المدير العام حصراً** | `GM` |
| **تغيير صلاحيات أو أسرار أو قواعد SoD أو سلسلة اعتماد** | **أربع عيون**: المنفّذ + معتمِد ثانٍ | `SYSADMIN` + (`DEPUTY_SYSADMIN` \| `CFO`) |

| الضابط | القاعدة |
|---|---|
| الصلاحية بالحد المالي لا بالمسمى | يمنع الالتفاف بتغيير المسمى |
| **لا معتمِد على منصب شاغر** | سلسلة تنتهي عند منصب غير مشغول = سلسلة ميتة؛ الطلب يقف إلى الأبد |
| **التفويض بمدة محددة** (≤ 90 يوماً · `valid_to` إلزامي) | الإجازة لا توقف العمل · والتفويض لا يصبح دائماً |
| **التفويض لا يلتف على فصل المهام** | مفروض في المُشغِّل نفسه (ADR-16c) — لا في سياسة مكتوبة |
| **لا اعتماد ذاتي** | من يطلب لا يعتمد طلبه مهما كان دوره — **مفروض في القاعدة** (§10-1) |
| كل اعتماد في التدقيق | من · متى · من أي جهاز · مع الملاحظة · و`reason` إلزامي للرفض والتجاوز |
| التصعيد الزمني | تجاوز `due_at` → تنبيه للمستوى الأعلى |

# 9. تخصيص التكلفة غير المباشرة

**هذا ما يربط الدورة الإدارية بالربحية.**

| التكلفة | أساس التخصيص |
|---|---|
| مشتريات تشغيلية (تغليف · قفازات · شريط) | مباشر للعميل إن أمكن · وإلا نسبة الأحداث |
| صيانة المستودع | نسبة المنصات المشغولة |
| رسوم حكومية للموظفين | مباشر للعميل المخصَّص له الموظف |
| **تكلفة الاستقدام** | تُطفأ على مدة العقد للعميل المخصَّص |
| عهد تالفة أو مفقودة | مركز التكلفة الذي حدثت فيه |
| مصروفات إدارية عامة | نسبة الإيراد أو عدد الموظفين |

**قاعدة إلزامية:** كل معاملة إدارية تحمل `cost_center`، و`client_id` **كلما أمكن**. المعاملة بلا مركز تكلفة تُرفض.

> بدون هذا تبقى الربحية تقديرية. التكلفة غير المباشرة في الشركات اللوجستية تتراوح بين 15% و25% — وتجاهلها يجعل كل هامش محسوب **مضخَّماً بهذه النسبة**.

# 10. المخطط — جداول `admin`

> **التعريف الحاكم في `A-governing/database/13` (والتعديلات في `13B`).** ما يلي وصف الجداول ومقتطف الأعمدة والقيود التي يتوقف عليها نصّ هذه الوثيقة. **لا يُبنى DDL من هنا** — النسخة النصّية انحرفت فعلاً عن المطبَّق مرتين (عمود مولَّد مستحيل، وقيدا اعتماد ذاتي صوريان).

| الجدول | الغرض | الأعمدة والقيود الحاكمة |
|---|---|---|
| `admin.budget_lines` | بند الميزانية والرصيد | `fiscal_year × cost_center × gl_account_id` فريد · `annual_amount`/`committed_amount`/`spent_amount` · **`available` مولَّد** = المتاح |
| `admin.purchase_requests` | طلب الشراء | `requested_by` · `cost_center` **إلزامي** · `client_id` إن وُجد · `budget_line_id` · `estimated_amount` (تحدّد شريحة الاعتماد §3-0) · `status` (`draft · pending_approval · approved · quoting · awarded · rejected · cancelled`) · **قيد لا-اعتماد-ذاتي فعلي** |
| `admin.vendor_quotes` | عروض الموردين | `is_selected` + **`selection_reason` إلزامي عند الاختيار** (ليس بالضرورة الأرخص — لكن السبب إلزامي) |
| `admin.purchase_orders` | أمر الشراء | `three_way_matched boolean` — **بوابة الدفع** · `variance_note` · `status` (`issued · partially_received · received · invoiced · paid · cancelled`) |
| `admin.petty_cash` · `admin.petty_cash_transactions` | العهدة النقدية | `limit_amount`/`current_balance` · `txn_type` (`advance · expense · settlement · return`) · **`constraint expense_needs_receipt check (txn_type <> 'expense' or receipt_url is not null)`** |
| `admin.assets` · `admin.asset_custody` | العهد والأصول | `asset_type` (يشمل `imile_id`) · **فهرس فريد جزئي `(asset_id) where returned_at is null`** = عهدة نشطة واحدة لكل أصل |
| `admin.gov_transactions` | المعاملات الحكومية | `stage` · **`stage_owner not null`** · `sla_days` · **`due_at` بمُشغِّل** · `government_ref` · `fees_paid` · **`fee_voucher_no` من سلسلة `GOV`** |
| `admin.approval_requests` · `admin.approval_steps` | محرّك الاعتماد الواحد | `request_type` · `amount` · `requested_by` · `current_step` · `approver_role`/`approver_user_id` · `delegated_from` · **`decision_note`** · **ضابط لا-اعتماد-ذاتي بمُشغِّل** |
| `admin.correspondence` | الوارد والصادر | `direction` · `reply_to_id` ذاتي المرجع · `assigned_to` + `due_at` |

## 10-1 التصحيحان البرمجيان المطبَّقان في v4

### (أ) `admin.gov_transactions` — العمود المولَّد المستحيل

```sql
-- ❌ ما كان في v1 — ترفضه PostgreSQL 16:
--   is_overdue boolean generated always as
--     (now() > stage_started_at + (sla_days || ' days')::interval) stored
--   ERROR: generation expression is not immutable

-- ✅ المعتمد: عمود موعد استحقاق يملؤه مُشغِّل، والتأخر شرط قراءة
  due_at timestamptz,     -- = stage_started_at + (sla_days || ' days')::interval
                          --   يُحدَّث بمُشغِّل عند كل تغيّر في stage أو sla_days

create index on admin.gov_transactions (stage_owner, due_at);
-- المتأخرة:  ... where due_at < now() and completed_at is null
```

**السبب:** `now()` غير ثابت (non-IMMUTABLE)، وPostgreSQL تمنع الدوال غير الثابتة في تعبير العمود المولَّد. والقاعدة نفسها تنطبق على `hr.recruitment_cases.due_at` (وثيقة 10 §5).

### (ب) ضابط «لا اعتماد ذاتي» — من قيد صوري إلى ضابط فعلي

```sql
-- ❌ ما كان في v1 — يمرّ دائماً ولا يفعل شيئاً:
--   constraint no_self_approval_placeholder check (true)
--   constraint no_self_approval check (approver_user_id is null or decided_at is null or true)

-- ✅ على admin.purchase_requests — قيد عمودي فعلي:
alter table admin.purchase_requests
  add constraint no_self_approval
  check (approved_by is null or approved_by <> requested_by);

-- ✅ على admin.approval_steps — مُشغِّل، لأن CHECK لا يقبل استعلاماً فرعياً:
create or replace function admin.reject_self_approval()
returns trigger language plpgsql as $$
declare v_requester uuid;
begin
  if new.approver_user_id is null or new.decision is null then
    return new;
  end if;
  select requested_by into v_requester
    from admin.approval_requests where id = new.request_id;
  if new.approver_user_id = v_requester then
    raise exception 'no_self_approval: الطالب لا يعتمد طلبه (request_id=%)', new.request_id
      using errcode = 'check_violation';
  end if;
  return new;
end $$;

create trigger trg_no_self_approval
  before insert or update of approver_user_id, decision on admin.approval_steps
  for each row execute function admin.reject_self_approval();
```

**السبب:** `check (true)` و`or true` يمرّان دائماً؛ و40 §C7 يشترط الضابط صراحةً. والاستعلام الفرعي ممنوع داخل `CHECK` في PostgreSQL، فالمُشغِّل هو المسار الوحيد الصحيح.

> **الاثنان مسجّلان في `_changelog/ADM-SCHEMA-NEEDS.md` §6 لوكيل المخطط.** ويُضاف إليهما: تفعيل RLS على كل جداول `admin` و`hr` و`identity` (الحارس G7: «Operational tables without RLS = 0»).
