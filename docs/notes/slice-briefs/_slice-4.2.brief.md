## Scenario (Gherkin outline — pg-tester writes the full `.feature`; NO handler-level tests — no api layer this round)
- Repository insert with a fresh `(sourceTable, sourceId, serviceId)` triple, `sourceId` pointing to a REAL, RLS-visible source row (seed one, e.g. a `wms.inbound_orders` row) → one row at `status='pending'`, `entity_id` equals the source row's own `entity_id`, one `platform.outbox` row + one audit row in the SAME transaction, `unit_price`/`amount` null.
- `sourceId` pointing to a source row that doesn't exist, or exists but is outside the caller's RLS-visible entities → typed not-found error, nothing written.
- `sourceTable` outside the closed list → typed `InvalidSourceTableError`, nothing written.
- Caller-supplied `clientId` that disagrees with the source row's own `client_id` → typed `ClientMismatchError`, nothing written.
- A SECOND insert of the SAME `(sourceTable, sourceId, serviceId)` triple → typed `DuplicateBillableEventError` (SQLSTATE 23505 by constraint name), nothing written — DETERMINISTIC test (round-1 finding 5): call `insertBillableEvent` twice in sequence within the test, don't rely on a timing race to exercise the DB-constraint path.
- `qty` non-finite (`NaN`, `Infinity`) or `<= 0` → typed error, nothing written (round-1 finding 2 fix — property test must include non-finite cases, not `noNaN: true`).
- Cross-entity isolation: RLS `entity_scope` already governs the table — a caller outside the source row's entity gets the not-found convention, proven non-trivially (an owner sees it, an outsider gets 0 rows / not-found, same query).
- Commercial-column masking: the audit row's `newValue` for `unit_price`/`price_source`/`amount` (all null on insert) — confirm `platform.sanitize_audit` handles null-for-commercial-column correctly.
- Property tests: `isFinitePositiveQty` (or equivalent, domain-level, NaN/Infinity/negative/zero cases), closed-list `sourceTable` validation, client-match validation — ALL in `domain/`, all with property tests (round-1 finding 3).
- Guards: G1 (RLS, inherited), G9 (outbox+audit pairing — one outbox row + one audit row per insert, same transaction), G11.
