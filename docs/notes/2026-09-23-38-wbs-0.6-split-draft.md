
**Rationale (D-124):** 0.6's original single row bundled six gates that need no infrastructure
(0.4 only — pnpm/Turborepo/ESLint boundaries, already DONE) with the seventh gate and the staging deploy
itself, which need the Tier-0 host (0.5, still WAITING_GM). That bundling made the entire CI pipeline wait
on Tier-0 provisioning even though five sixths of it — lint, unit, integration against an ephemeral
database, the guard suite, a security scan — can run on GitHub Actions today, unblocking real CI coverage
for every PR without waiting on 0.5. Splitting is a **pure sequencing decision, no schema, no scope
change** — the seven gates named in doc 36 §4-3 are unchanged; DEPLOYMENT PIPELINE in CLAUDE.md is
unchanged.
