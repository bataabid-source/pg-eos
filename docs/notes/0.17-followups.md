## 1. `assignRole` has no caller-authorization, second-approver, or audit layer (G-01)

Doc 22 §2-2/§2-3 requires, for any change to role/permission structure: the caller hold
`identity.structure.manage`; a second approver (`DEPUTY_SYSADMIN` or `CFO`); an audit-log row
with before/after values. None of this is buildable today:
- `identity.structure.manage` is seeded nowhere in `database/schema/*` (confirmed by grep).
- `identity.user_roles` (01-Data-Model.sql:249-257) has no approver column, and no separate
  approval-request table exists for this flow.

`packages/identity/src/rbac.ts`'s `assignRole` therefore performs NO caller-authorization check
and NO second-approver/audit step — it only relies on the existing `identity.check_sod()` /
`trg_sod` trigger (13B:539-555) for the one invariant the schema already enforces (SoD). This is
documented directly in the function's own doc-comment. **`assignRole` must not be wired to an
API endpoint or admin UI as if it already implements doc 22's "structure editable without
deploy" clause** — that requires the schema addition below first.

Needed (Master-owned, `database/schema/*`, next available migration slot): a
`identity.structure.manage` permission row, plus either an approver column on
`identity.user_roles` or a parallel approval-request table, plus a defined audit-log write path
for structure changes.

## 2. `identity.sessions` has no index on `token_hash`

`identity.sessions` (01-Data-Model.sql:267-277) is indexed only on `(user_id, expires_at)`.
`verifySession` looks up by `token_hash` — the busiest path in the auth mechanism — so every
verification is a sequential scan. Needed: a migration adding an index on
`identity.sessions (token_hash)`.

## 3. `platform.thresholds` has no production seed rows for OTP/session limits

No row exists for `identity.otp.expiry_minutes` or `identity.session.lifetime_minutes` (checked
every `insert into platform.thresholds` block in 13B — confirmed absent both times, round 1 and
round 2 of this task). `packages/identity`'s tests seed and clean up their own fixture rows under
these keys; `getThreshold` throws naming the key rather than falling back to an embedded default.
Until real seed rows land, two things stay true: (a) no live login flow can use this package
without first seeding these keys itself, and (b) the tests' fixture cleanup carries one accepted,
narrow flake window against concurrent worktree runs on the shared dev database (documented in
each test file's own header) that disappears once real seed rows make every fixture insert a
no-op `on conflict do nothing`.
