## What `main` has today, and therefore what is genuinely still missing

`aa46787`'s entire deliverable is the **proof**, not schema: one integration test,
`modules/platform/tests/integration/schema-invariants.test.ts`, which proves both halves of doc
38's 0.9 acceptance criterion against the already-applied schema — 100 genuinely concurrent
`platform.next_doc_no()` calls via a real `pg.Pool` + `Promise.all`, and a
tamper/detect/restore round-trip on `platform.verify_audit_chain()` in an exception-safe
`try/finally`.

Alongside it, `database/schema/guards.sql` carries G13 in a **pure-SQL form**: 100 calls from
`generate_series(1, 100)` inside a single transaction on a single connection. That satisfies the
guard's pass condition, but it is explicitly *not* doc 40 Part F's governing form — Part F line
~643 specifies `pgbench -c 100 -t 1 -f tests/guards/next_doc_no.sql`, then
`select count(distinct doc_no) from platform.doc_no_probe;` ⇒ 100 unique. `guards.sql`'s own
header comment (line 14) says as much.

Consequently, on `main` today:

- `platform.doc_no_probe` **does not exist** anywhere in `01 · 13 · 13B · 019`.
- The directory `tests/guards/` **does not exist**.
- No pgbench-based, real-cross-connection form of G13 exists (concurrency *is* proven, but
  through Node, not through the tool doc 40 names).
- No `.feature` file exists for 0.9.

Both abandoned branches were attacking exactly that gap. Whether closing it is worth a task at
all is a Master/GM call — this note only records that the work exists and where.
