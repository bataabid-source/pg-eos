## 0.15 — Document engine: templates, bindings, Chromium PDF, bilingual RTL (2026-09-22)

- **Delivered (doc 38 acceptance: "Arabic/English PDF renders correctly; entity header auto-applied").** New package `packages/documents` — `renderDocument(pool, { templateId, entityId, data })` reads a `platform.document_templates` row and target `platform.entities` row, compiles the template's Handlebars `body_html` with a context merging the entity's header fields (`nameAr`, `nameEn`, `legalNameAr`, etc.) and caller-supplied `data`, composes a full HTML document with an auto-applied entity header/footer wrapper (RTL default, Cairo font embedded offline via `@fontsource/cairo` as base64 data URIs — no CDN/network dependency), and renders to PDF via a shared, lazily-launched headless Chromium instance (`puppeteer`). Rejects when an entity-scoped template (`document_templates.entity_id` set) is used for a different entity; validates `page_size`/`orientation` against a known set and throws clear error for invalid values (these columns are plain `text`, no DB CHECK constraint yet — application-level invariant).
- **Scope decision (recorded explicitly — this slice's deliverable vs. future binding/numbering/recording).** Built the RENDERING ENGINE ITSELF (template + entity + document-specific data → bilingual PDF with entity header/footer auto-composed), matching doc-38 criterion exactly. ## 0.12 — `packages/events`: outbox relay + subscriber registry (2026-09-22)

- **Delivered (doc 38 acceptance: "Event written in same tx as state; relay at-least-once; subscriber idempotent").** New package `packages/events` — (1) `writeOutboxEvent(tx, input)` writes a `platform.outbox` row using the ambient transaction scoped to the same `drizzle` handle `withContext` (from 0.11) passes to its callback, so rows commit or roll back with the caller's work, never a third case. (2) `registerSubscriber(name, handler)` + `clearSubscribers()` (test-only, not exported) + `listSubscribersWithNames()` — an in-memory registry. (3) `relayOnce(pool, opts?)` — polls unpublished `platform.outbox` rows (optionally filtered by `opts.eventType`), invokes every registered subscriber for each row, marks a row published only if ALL subscribers succeed; a row whose subscriber throws stays unpublished so the next `relayOnce` call redelivers it — this redelivery IS the at-least-once mechanism. (4) `packages/events/catalog.ts` — the event-name registry (CLAUDE.md's PARALLEL LANES section references it as frozen for cross-module event consumption); starts empty by design (no module has shipped real domain events yet), grows as future slices ship their domain-event publishers.
- **Slice history: exceptionally deep, three full review passes, mirroring 0.11's depth.** Round 1: pg-tester wrote genuine RED tests against a non-existent package; pg-backend built it to green. pg-reviewer FAIL(16): (a) correctness blocker — `relayOnce` with zero registered subscribers silently marked every pending row published without delivering it (permanent, silent event loss); (b) correctness blocker — the SELECT was completely unscoped, a "limit respected" test swept up pre-existing shared-database rows and destructively marked them published (data loss); plus 14 more (process-global `pg.types.setTypeParser` mutating on test-local int8-string problem; false architectural parity claim with 0.11's `withContext` exemption; `writeOutboxEvent` imposing undocumented G9 obligation; dangerous test-only export on public barrel; missing `last_error` subscriber attribution; no attempt ceiling/dead-letter documentation; mid-batch subscriber re-read; missing `catalog.ts`; concurrency-safety gap). A background-worker/system-role RLS access strategy is a future G-01 schema-change request, not invented here. (3) No attempt ceiling or dead-letter policy — `attempts` is tracked but never capped; a permanently-failing row can head-of-line-block a batch (sorted first by id) — documented as a known limitation. (4) `packages/events/catalog.ts` starts empty by design — grows as future slices ship real domain events.
